# URL Shortener — DevOps Practical Assignment

Status: **Part 1 (Docker Compose) complete and verified.** Part 2 (Kubernetes) and Part 3
(operations/runbook) not started yet.

## Components
- **API** — Python + FastAPI. Creates short URLs, redirects visitors to the original URL.
- **PostgreSQL** — stores URL mappings (source of truth).
- **Redis** — caches URL lookups (cache-aside pattern: check Redis first, fall back to Postgres
  on a miss, then write back to Redis).

## Endpoints

| Endpoint | Description |
|---|---|
| `POST /shorten` | Body: `{"url": "https://..."}`. Creates a short URL. Returns `{"short_code": "...", "short_url": "..."}`. |
| `GET /{short_code}` | Redirects (HTTP 302) to the original URL. Returns 404 if the code doesn't exist. |
| `GET /health` | Returns `{"status": "ok"|"degraded", "postgres": bool, "redis": bool}` — reports whether the API and each dependency are reachable. |

Interactive docs (auto-generated by FastAPI) are available at `/docs` once the API is running.

**Design notes:**
- Short codes are base62-encoded Postgres row ids (not random strings) — deterministic, no
  collision handling needed, and no `short_code` column is stored (it's derived on every request).
- The API retries connecting to Postgres/Redis on startup (up to 10 attempts, 2s apart) instead of
  assuming they're immediately ready.

## Part 1 — Run it with Docker Compose

**Requirements:** Docker with Compose (Docker Desktop, or Docker Engine + the Compose plugin).

```bash
# 1. Copy the example env file and adjust values if you want (defaults work as-is for local use)
cp .env.example .env

# 2. Build and start everything (API + Postgres + Redis)
docker compose up --build
```

This builds the API image, starts Postgres and Redis, waits for both to report healthy, then
starts the API. Once running:

```bash
# Health check
curl http://localhost:8000/health

# Create a short URL
curl -X POST http://localhost:8000/shorten \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/some/very/long/path"}'
# -> {"short_code":"1","short_url":"http://localhost:8000/1"}

# Use it (follow the redirect with -L, or drop -L to just see the 302 + Location header)
curl -L http://localhost:8000/1
```

Or just open `http://localhost:8000/1` (or whatever code you got back) in a browser — it redirects
directly.

**To stop:**

```bash
docker compose down          # stops and removes containers, keeps the Postgres data volume
docker compose down -v       # also wipes the Postgres data volume (full reset)
```

**Verifying Postgres data survives a restart:** create a short URL, then run
`docker compose down` (no `-v`) followed by `docker compose up -d` again — the same short code
will still resolve, because the data lives in a named Docker volume (`postgres_data`), independent
of the containers themselves.

## Notes / assumptions / known limitations
- Short codes are sequential and therefore guessable — acceptable for this assignment's scope, not
  something to rely on for access control.
- No CI/CD pipeline — out of scope for the assignment's stated deliverables; would add a basic
  build+test GitHub Actions workflow as a stretch goal if time allows.
- See `documentation.md` for the full running decision log (why each choice was made) and
  `explanations.md` for concept write-ups (cache-aside, base62 encoding, Docker/Compose
